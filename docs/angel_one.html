Angel One CLI

Standalone command-line interface for Angel One — connectivity checks, portfolio inspection, manual orders, the live auto-trader, the paper-trader, and a full performance report engine.

Introduction

scripts/angel_one.py is a single, self-contained CLI that wraps every interaction with the Angel One SmartAPI. It loads the project's .env, authenticates through TOTP, caches the session at data/angel_session.json (18-hour TTL), and exposes eight sub-commands grouped into three areas:

  • Inspection — status, portfolio
  • Manual — order
  • Engine — auto-trade, paper-trade, *-status, paper-summary, paper-report, paper-trade-and-report
This script and stock_analyzer.py are now fully decoupled. stock_analyzer.py only runs the analysis and writes picks to data/stock_reports/; angel_one.py consumes those picks and acts on them. Use paper-trade-and-report for a single command that gathers picks (running the analyzer if stale), ticks the paper-trader, and pushes the report image to WhatsApp or Telegram.

status

Verifies SmartAPI authentication and prints holdings count + cash + the master trading-enabled flag. Use this as the first check on any new machine.

python scripts/angel_one.py status
Angel One available: True
Holdings: 24  Cash: ₹125,432.10  Trading enabled: False

portfolio

Read-only snapshot of your account: cash, net-worth, used margin, holdings table with live LTPs & P&L, and intraday positions.

python scripts/angel_one.py portfolio

Output sections:

  • Cash / Net / Margin
  • Holdings — symbol, qty, avg, LTP, P&L, P&L %
  • Intraday positions — first 10 with net qty + P&L

                                  --order-type SL --product INTRADAY \

Live trade. When ANGEL_TRADING_ENABLED=1, the order goes straight to the exchange. There is no extra confirmation prompt.

auto-trade

The live auto-trader. Reads data/stock_reports/ picks, polls LTPs, and BUYs / SLs / TGTs in real-time. Always dry-runs by default; set both ANGEL_TRADING_ENABLED=1 AND AUTO_TRADE_DRY_RUN=0 to transmit.

FlagPurpose
--onceSingle tick (cron-friendly) instead of foreground loop
--refreshRe-run the analyzer to regenerate today's picks before trading
# Foreground loop, polls every 60s during market hours
python scripts/angel_one.py auto-trade

# Single tick (cron-friendly)
python scripts/angel_one.py auto-trade --once

# Refresh picks via analyzer, then start the loop — fully autonomous
python scripts/angel_one.py auto-trade --refresh

State persists at data/auto_trader_state.json. See Trader Config for tunables.

auto-trade-status

Prints the live trader's current state — open trades, today's realised P&L, and halt status (if the daily-loss limit was hit).

python scripts/angel_one.py auto-trade-status

paper-trade

Identical decision logic to auto-trade, but never transmits. Uses a virtual cash balance (PAPER_STARTING_CASH, default ₹100k) and tracks cumulative P&L across days at data/paper_trader_state.json.

FlagPurpose
--onceSingle tick instead of foreground loop
--refreshAlways re-run the analyzer first to regenerate today's picks
--refresh-if-staleRun the analyzer only if today's picks don't exist yet
# Foreground loop
python scripts/angel_one.py paper-trade

# Single tick
python scripts/angel_one.py paper-trade --once

# Fully auto: regenerate picks if needed, then loop
python scripts/angel_one.py paper-trade --refresh-if-stale

# Force a fresh analysis even if today's picks exist, then loop
python scripts/angel_one.py paper-trade --refresh
Paper mode forces dry_run=True regardless of any env var. There is no way to accidentally transmit real orders from this command.

paper-summary

Compact console summary — today's date, cumulative P&L, win rate, open positions, closed trades, and last 10 historical trades.

paper-trade-and-report

One-shot composite that owns the full analyze → trade → report loop. This is the canonical command for ad-hoc snapshots and is what the GitHub Actions workflow uses for every market-touch event:

  1. If today's picks don't yet exist in data/stock_reports/, runs stock_analyzer.run_report() internally to generate them.
  2. Ticks the paper-trader once with live LTPs (Angel One). Any entries hit, SLs hit, or targets hit are recorded into data/paper_trader_state.json.
  3. Renders the compact report PNG and pushes it through the configured channel (WhatsApp by default).
FlagDefaultPurpose
--channel {whatsapp,telegram}whatsappWhere to push the report image
--refreshoffForce re-run of the analyzer even if today's picks already exist
--at-eodoffEOD pass: square off all open intraday positions and skip new entries
# Default ad-hoc snapshot (refresh-if-stale, tick, send to WhatsApp)
python scripts/angel_one.py paper-trade-and-report

# Push to Telegram instead
python scripts/angel_one.py paper-trade-and-report --channel telegram

# 15:30 IST end-of-day square-off + final report
python scripts/angel_one.py paper-trade-and-report --at-eod

# Force a fresh analyzer run even if today's picks exist
python scripts/angel_one.py paper-trade-and-report --refresh
Equivalent to running paper-trade --once --refresh-if-stale followed by paper-report --send, but as a single atomic step with one cleaner invocation.

Decision Logic

Each tick the engine performs three steps in order:

  1. Exit checks — every open trade's LTP is compared against its SL and target; matching trades are closed first.
  2. Halt check — if today's realised P&L drops below -AUTO_TRADE_MAX_DAILY_LOSS_INR, the trader halts for the rest of the day.
  3. New entries — for each pick whose live LTP is within ±0.5% of the entry level and still above SL, a sized BUY is issued (subject to max_positions and available cash).

Position Sizing

Quantity per trade is computed as:

qty = int((available_cash * MAX_PCT_PER_TRADE) // entry_price)

So with the defaults — ₹100k cash, 10% per trade, ₹500 share — the trader buys (100,000 × 0.10) // 500 = 20 shares. Quantities below AUTO_TRADE_MIN_QTY are skipped entirely.

Workflow: Paper Trading

Recommended (one-command)

# Refreshes picks if today's report doesn't exist yet, then loops the
# paper trader — fully autonomous from a single invocation.
python scripts/angel_one.py paper-trade --refresh-if-stale

Manual (two-step)

# 1. Generate today's picks
python scripts/stock_analyzer.py --dry-run

# 2. Start the paper trader (loops every 60s during market hours)
python scripts/angel_one.py paper-trade
#  ^ Ctrl+C to stop. Or run with --once and schedule via Task Scheduler.

# 3. End-of-day: full performance report
python scripts/angel_one.py paper-report

# 4. Optional: push report to Telegram nightly
python scripts/angel_one.py paper-report --send --channel telegram

The paper book is a separate file (paper_trader_state.json) so running paper and live modes side-by-side is safe.

Workflow: Live Trading

Real money. Run paper-trade for a few weeks first and review the win-rate / profit-factor in paper-report before flipping the switches below. 
# 1. Verify connectivity
python scripts/angel_one.py status

# 2. In .env (or session env) set BOTH:
$env:ANGEL_TRADING_ENABLED = "1"
$env:AUTO_TRADE_DRY_RUN    = "0"

# 3. Optional but recommended risk caps
$env:AUTO_TRADE_MAX_POSITIONS = "3"
$env:AUTO_TRADE_MAX_DAILY_LOSS_INR = "2000"
$env:AUTO_TRADE_MAX_PCT_PER_TRADE  = "0.05"
$env:AUTO_TRADE_NOTIFY_CHANNEL     = "telegram"

# 4. Run
python scripts/angel_one.py auto-trade

# Or do it all in one command — regenerate picks, then trade
python scripts/angel_one.py auto-trade --refresh

Stock-Analyzer Bridge

The analyzer (stock_analyzer.py) and this script are decoupled and both standalone:

  • stock_analyzer.py only runs the analysis and writes picks to data/stock_reports/ (plus optional report image / PDF).
  • angel_one.py reads those picks and acts on them — paper or live trading, portfolio inspection, manual orders.

The composite paper-trade-and-report command runs the analyzer internally if today's picks are missing, so a single invocation handles the full flow:

# Analyzer-only (writes data/stock_reports/<today>.json)
python scripts/stock_analyzer.py --dry-run

# Paper trade against the latest picks (refreshes via analyzer if stale)
python scripts/angel_one.py paper-trade --once --refresh-if-stale

# Single command: gather picks → tick paper trader → push report image
python scripts/angel_one.py paper-trade-and-report

State persistence

Paper-trader state (data/paper_trader_state.json + the data/paper_reports/ archive) is persisted across runs by committing to a dedicated orphan branch — paper-trader-state — at the end of every job. This keeps runtime noise out of master history while still making state survive across days/weekends. The concurrency.group: angel-one-trader setting serializes runs so two schedules can never overwrite each other's state.

Manual dispatch

Both workflows expose workflow_dispatch with a dropdown of vetted commands. angel_one.yml additionally supports a reset_paper_state=yes input which wipes the state branch's data files at job start — useful when you want to re-seed cash or start a fresh paper-trading window.

Required secrets / vars

  • angel_one.yml only: ANGEL_API_KEY, ANGEL_CLIENT_CODE, ANGEL_MPIN, ANGEL_TOTP_SECRET, vars.PAPER_STARTING_CASH
  • both workflows: GOLD_PHONE_NUMBER, GREEN_API_INSTANCE, GREEN_API_TOKEN, TELEGRAM_BOT_TOKEN, TELEGRAM_CHAT_ID

Safety Rails

Master kill-switch

ANGEL_TRADING_ENABLED=0 blocks every order regardless of sub-command. The default is off.

Paper mode is hard-locked

paper-trade forces dry_run=True; no env var overrides this.

Daily loss halt

Realised P&L ≤ -AUTO_TRADE_MAX_DAILY_LOSS_INR halts new entries for the rest of the trading day.

Per-trade cap

Position sizing is capped at MAX_PCT_PER_TRADE of available cash — protects against fat-finger entries.

Position cap

MAX_POSITIONS prevents the trader from opening more concurrent trades than your risk model allows.

Stop-loss is mandatory

Every entry uses an ATR-derived SL from the analyser. Trades without an SL on the pick are skipped entirely.
